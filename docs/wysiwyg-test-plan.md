# 实时渲染 ⇄ 源码：两面一致性的测试方案（Test Plan）

> 对象：Lumin 的**双编辑面**——`wysiwyg`（Tiptap 所见即所得）、`source`（源码 textarea，分屏右栏与
> 全屏源码模式共用同一个常驻元素）、`split`（两面同时可见），以及嵌在 wysiwyg 里的第四个写入者
> `codeblock`（代码块内的 CodeMirror）。
>
> 这份文档回答三件事：**要验什么性质**、**用什么手段验**、**加东西时往哪儿加**。
> 执行结果与问题台账见本文 §9（每轮跑完更新）与手册 §4.68。

---

## 1. 为什么需要一个专门的方案

Wave 1 已经把「Markdown 往返保真」钉住了（`tools/fixtures/md/` 31 份夹具 + `tools/lib/md-fidelity.js`
判级器 + `_verify-md-fidelity.js` 三层断言）。但那条线只回答**一半**问题：

* 它把内容装进编辑器、走一遍序列化器，比的是 **文本**；
* 它**不碰模式切换**，也**不看渲染**，更没有「极端规模下还成不成立」的维度。

而用户对「所见即所得」的信任来自三件同时成立的事：

1. **切来切去内容不变**（切面本身没有副作用）；
2. **两面说的是同一篇文档**（结构、顺序、可见文本一致）；
3. **该看见的真的看得见**（渲染结构对，不是「文本对了但样式没了」）。

所以本方案把「两面一致性」拆成 6 类**可判定属性**（§2），再按成本从低到高分 5 层手段（§3）。

---

## 2. 质量模型：6 类可判定属性

| 属性 | 判据（可自动判定） | 违反时的用户可见形态 |
| --- | --- | --- |
| **P1 内容守恒** | 任一编辑面往返后，`md-fidelity` 判级不劣于 `normalized`（`lossy` = 回归） | 内容被吃掉/被改写（最严重） |
| **P2 幂等与稳定** | ①同一内容再走一遍产出**逐字相同**；②无编辑时切面**不改**真源内容 | 每次保存/切换 git diff 都是噪声 |
| **P3 结构一致** | 块级/行内结构计数（标题层级、围栏、表格行列、列表项、数学块、HTML 块）往返后一致 | 结构塌陷（表格变段落、列表被拆散） |
| **P4 位置语义** | 切换前后光标/选区落在**同一逻辑位置**（切换后立即输入的哨兵字符出现在预期邻域）；滚动比例保持 | 切一下就跳到文首/文末，续写跑到别处 |
| **P5 状态语义** | ①只看不编辑 → `dirty` 保持 false；②编辑后切面 → `dirty` 保持 true 且内容不丢；③撤销要么成功、要么无副作用，**绝不产生损坏内容**；④保存后磁盘字节 = 真源内容（按行尾/编码展开） | 「我什么都没改却提示未保存」/ 撤销把文档弄坏 |
| **P6 性能预算** | 大文档下打开、切面、输入的耗时不超过预算（§7） | 大文件切一下就卡住好几秒 |

**判级口径**沿用 Wave 1 的既定规矩：只承认**能在 CommonMark 语义上站住的保义改写**（19 条规则，
`md-fidelity.js` 的 `RULES` 导出）；需要「猜」的一律判 `lossy` 让人去看，**不许拿规则把真问题糊过去**。

## 3. 五层手段（成本从低到高，快反馈在下）

```
L0 纯函数性质测试        毫秒级，进 npm run ci（tests/*.test.mjs）
   └ 生成器自身性质 + 判级器性质（规范化幂等、判级对称、绝不抛异常）
L1 黄金夹具（既有）      秒级，进默认矩阵（_verify-md-fidelity.js：31 夹具 + 字节级 + 幂等）
L2 双面端到端矩阵        十秒级，进默认矩阵（_verify-surfaces.js：切面/位置/状态/渲染结构）
L3 生成式语料 fuzz       分钟级，进默认矩阵（_verify-surface-fuzz.js：可复现种子的语料 × 不变量）
L4 极端 / 边界 / 压力    分钟级，进默认矩阵（_verify-surface-stress.js：规模、畸形输入、时间预算）
```

**为什么这样分**（而不是「多写点 CDP 套件」）：

* **反馈速度分层**：改一行序列化器就能在 `npm run ci` 里用毫秒级性质测试拿到信号；CDP 层只验
  那些「必须在真浏览器 + 真编辑器里才存在」的东西（DOM 结构、计算样式、光标、账本）。
* **可复现**：L3/L4 全部由**种子**驱动（`LUMIN_FUZZ_SEED` / `LUMIN_FUZZ_COUNT`），失败时打印种子与
  最小复现片段，别人一条命令就能重现。
* **可聚合**：所有套件沿用仓库既有约定，输出末行 `--- N/M PASS`，由 `tools/run-suites.js` 汇总成矩阵。
* **可扩展**：加构造 = 往注册表加一条；加渲染预期 = 往表格加一行；加极端用例 = 往矩阵加一行（§8）。

## 4. 不变量清单（I1–I12）

每条不变量都要能回答「违反时长什么样」，否则不算可判定。**I1–I3 是闸门（FAIL）**，其余是闸门或
诊断（下表注明），诊断项默认只报不红，避免把「观感差异」当成回归。

| # | 不变量 | 判据 | 层级 | 类型 |
| --- | --- | --- | --- | --- |
| I1 | 内容守恒 | `classify(src, produced)` 不劣于 `normalized` | L1/L2/L3/L4 | 闸门 |
| I2 | 往返幂等 | `produced → 再走一遍 == produced`（逐字） | L1/L3 | 闸门 |
| I3 | 切面无副作用 | 只看不编辑时，切面前后真源内容**逐字相同**、`dirty` 不变 | L2 | 闸门 |
| I4 | 切面稳定 | `wysiwyg → source` 读到的文本 == 上一次 source 读到的文本 | L2/L3 | 闸门 |
| I5 | 结构计数守恒 | 标题/围栏/表格/列表项/数学块/HTML 块计数一致 | L3 | 闸门 |
| I6 | 源码面完整性 | `textarea.value` == 真源内容（含 front matter、文末换行） | L2/L3 | 闸门 |
| I7 | 渲染面完整性 | PM 文档可见文本覆盖源文档的可见文本（顺序一致、无截断） | L2/L3 | 闸门 |
| I8 | 渲染结构正确 | 每种构造在 DOM 里落到预期元素，且关键计算样式符合预期（§6.3） | L2 | 闸门 |
| I9 | 分屏同世代 | 任一面输入后，两面都收敛到同一世代（账本无落后） | L2 | 闸门 |
| I10 | 撤销安全 | 切面后 Ctrl+Z：内容要么回到上一版、要么不变，**绝不出现损坏/半截文档** | L2 | 闸门 |
| I11 | 保存一致 | 保存后磁盘字节 = 真源内容按行尾/编码展开的结果 | L2/L4 | 闸门 |
| I12 | 时间预算 | 极端规模下打开/切面/输入耗时 ≤ 预算（§7） | L4 | 闸门（阈值给宽） |

**内容丢失的独立诊断**：当 I1 判 `lossy` 时，除打印 `md-fidelity` 的行级差异外，再做一次
「非标记字符序列比对」（去掉空白与 Markdown 标记字符后比较字符序列）。它**不参与判级**
（会把保义改写当成丢失），只用于把失败分诊成「真丢内容」还是「被重写了标记」——分诊决定修法。

## 5. 生成式语料（L3）设计

### 5.1 构造注册表

`tools/lib/md-gen.js` 里维护一张**构造表**（`CONSTRUCTS`），每条构造 = 一个能写出合法片段的函数：

```js
{ id: 'heading-atx', cat: 'block', weight: 3, make(rng) { return { md: '## 标题', tags: ['heading'] } } }
```

覆盖四大类（与 `md-fidelity.js` 的 19 条规则一一对上，规则覆盖不到的地方就是新缺口）：

* `block`：ATX/Setext/闭合 ATX 标题、段落、分割线（3 种写法）、引用（含懒续行、嵌套）、围栏代码
  （```/~~~、info、内容含反引号、空块、块尾空行）、缩进代码、无序/有序列表（三种标记、`)` 分隔符、
  起始编号、紧凑/松散、1–4 层嵌套）、任务列表、表格（对齐、转义竖线、单元格内行内码、空单元格）、
  HTML 块（div / 注释 / `<pre>`）、front matter（合法/伪 front matter）、`$$` 公式块（单行/多行）、
  引用式链接定义。
* `inline`：强调（`*`/`_`/`**`/`__`/`***`、词内下划线、嵌套）、行内代码（1–3 个反引号、内含反引号）、
  链接（行内/标题/尖括号/引用式/自动链接/裸 URL）、图片（行内/带链接/带标题）、行内 HTML、行内公式、
  转义序列、HTML 实体、硬换行（`\` 与两空格两种）、软换行。
* `unicode`：CJK 与标点、emoji/ZWJ/旗帜、组合附加符、RTL（阿拉伯/希伯来）与双向混排、零宽字符、
  NBSP、制表符、长单词、代理对边界。
* `mutation`（不是构造而是**文档级变异**）：行尾 CRLF/LF/CR、BOM、文末无换行、连续空行、
  前导/尾随空行、超长行、块之间无空行（粘连）。

### 5.2 组合策略（真正找出问题的地方）

单条构造写对不难，**难在两两相邻**。所以生成器按三层组合：

1. **块序列**：按权重抽 N 个块构造，用「空行 / 单个换行 / 不放分隔」三种接缝拼接；
2. **上下文包裹**：把块塞进 `引用里`、`列表项里`、`表格单元格里`、`围栏代码里`（后者用于验证
   「代码块里的一切都不该被当 Markdown」）；
3. **行内混入**：往段落文本里按概率插入行内构造，并特意制造**标记相邻**（`*a*b*`、`a_b_c`、
   `**a *b* c**`、`` `a`*b* ``、`$a*b$`）——历史缺陷（`$a * b$` 被切开、下划线误判）全部出在这里。

### 5.3 可复现与最小化

* 种子驱动：`mulberry32(seed)`，同一 seed 在任何机器上产出**同一份语料**（这也是 L0 里
  「生成器确定性」那条单测要钉的）。
* 失败最小化：套件发现 `lossy`/不稳定时，按块贪心删除（delta debugging 的简化版）产出**最小复现**，
  写进报告 JSON（`%TEMP%\lumin-surface-fuzz-report.json`）并打印前 3 条。

## 6. 极端 / 边界 / 特殊输入矩阵（L4）

### 6.1 规模与结构极端

| 用例 | 规模 | 想抓什么 |
| --- | --- | --- |
| 巨型文档 | ~1 MB / ~1.2 万行 | 是否有 O(n²)（每键重排、每行重解析） |
| 超长单行 | 200 KB 一行 | 行内解析/装饰是否退化；光标定位 |
| 极深嵌套 | 100 层列表 / 50 层引用 | 递归深度、栈溢出、缩进归一 |
| 海量块 | 2000 个围栏 / 300 行表格 / 5000 处行内样式 / 1000 个公式 | 节点与装饰数量带来的卡顿 |
| 超宽表格 | 60 列 × 200 行 | 表格列宽计算与选择 |

### 6.2 畸形与边界输入

空文档、只含空白、单字符、只有 front matter、只有代码围栏、**未闭合**围栏/强调/链接/公式/HTML 注释/
front matter、围栏被内容提前闭合（` ```` ` 里放 ``` ）、表格缺分隔行、列表标记后无空格、
`- - -` 与 `---` 的歧义、`$$` 与 `$` 的歧义、CR-only 行尾、混合行尾、超长 URL、`<` 与 `&` 裸用、
非法 UTF-16（孤立代理项）、控制字符（除 \t\n）。

### 6.3 渲染结构预期（I8 的清单，可扩展）

每种构造一行：`选择器 + 谓词`。至少覆盖：

* 标题 h1–h6：标签正确 + `font-size` **严格递减**（抓「渲染成同一个大小」）；
* 段落/引用/列表：引用有左内边距、列表项有可见标记、任务列表有 `input[type=checkbox]`；
* 表格：列对齐落到 `text-align`，单元格是 `td/th`，边框非 none；
* 代码块：等宽字体 + 背景色 ≠ 透明 + 语言标签（有 info 时）；
* 行内代码/粗斜体/删除线/下划线：`code`/`strong`/`em`/`del`/`u` 标签；
* 图片：`img` 且渲染宽度 > 0（相对路径与 data URI 两种）；
* 公式：行内渲染出 `.katex`，块级是 `[data-md-math-block]`；
* mermaid：渲染出 `svg`（异步，需等待）；
* front matter：`pre[data-md-frontmatter]` 且文本 = 原文；
* 分割线：`hr` 且高度 > 0。

## 7. 度量与预算

* **测什么**：`打开/装载`（`openPath` → 编辑器就绪）、`wysiwyg→source`、`source→wysiwyg`、
  `入一个字符的可见延迟`、`保存耗时`。页面侧用 `performance.now()` 夹住关键调用，套件侧计时兜底。
* **预算怎么定**：先跑一轮**只报告不判**，取实测值，再在套件里写成 `预算 = max(50ms, 实测 × 3)`
  的量级（表里写死具体数字，避免「预算随实现漂移」）。比「绝对值很小」更重要的是**回归可见**：
  预算超标就是 FAIL，并把实测值打出来。
* **抗抖动**：每个计时用例先做 1 次预热（不计入），取 2 次中的**最小值**；断言用宽松上限。
* **内存**：`performance.memory.usedJSHeapSize`（Chromium 专有）只**报告**不判定 —— 在 Electron 里
  它的口径不稳定，拿来当门禁会变成噪声源。

## 8. 怎么扩展（加东西的人只看这一节）

| 想加什么 | 往哪儿加 | 注意 |
| --- | --- | --- |
| 一种新的 Markdown 构造 | `tools/lib/md-gen.js` 的 `CONSTRUCTS` 加一条（带 `tags`） | `tags` 会出现在失败报告里，写清楚构造名 |
| 一种新的文档级变异 | 同文件 `MUTATIONS` 加一条 | 变异必须**保义**或**已知会失义**（后者进 `EXPECT`） |
| 一条新的不变量 | `tools/lib/surface-invariants.js` 加一个导出函数 + `tests/surfaceInvariants.test.mjs` 加断言 | 不变量必须是纯函数（输入文本/计数，输出判定） |
| 一条新的渲染预期 | `tools/_verify-surfaces.js` 的 `RENDER_SPECS` 加一行 | 用「选择器 + 谓词」表达，别写一次性脚本 |
| 一个极端用例 | `tools/_verify-surface-stress.js` 的 `CASES` 加一行 | 必须给规模与预算；用例要能单独开关 |
| 一条新的端到端切面断言 | `tools/_verify-surfaces.js` | 复用 `tools/lib/harness.js`，不另写 CDP 样板 |

复现；套件末行固定 `--- N/M PASS`。

### 9.2 已知限制（不打算修的，写清理由）

| 限制 | 理由 |
| --- | --- |
| 「保存补文末换行」与 `no-final-newline` 字节用例保持 SKIP | 与 Typora/VS Code 同款保义改写（规则 18），已在 `EXPECT.json` 记录 |
| Shift_JIS 与 GBK 的无 BOM 双字节编码歧义 | 没有元信息时任何编辑器都只能猜；缓解手段是「选择编码重新打开」+ 每文件记忆 |
| 判级器**不**新增「块间空行」「引用行软换行」两条规则 | 这两条要正确实现必须让规范化器变成「引用感知 + 块类型感知」的递归实现，改错会把真缺陷糊过去；当前改用「文档树签名同构 + 哨兵词齐全」作为硬判据，lossy 只作分诊线索（见 §4 I1 的分诊口径） |

### 9.3 下一轮建议（按性价比排序）

1. **F4/F5（代码块虚拟化）**：只给视口内的代码块挂 CodeMirror，块数相关的成本从线性降到常数 —— 收益最大，也最影响「粘一篇大笔记」的体验。
2. **F3（大文档路径 profile）**：977KB 的装载/回灌各 16s，先量出热点（解析？归一化？装饰？大纲？），再决定 memo 还是分片。
3. 判级器补两条规则（引用感知的规范化），把 L2/L3 的「分诊」升级成「直接判定」。
4. 把 L2/L3 的探针接进 CI 的可选 job（需要桌面会话，参考 README 的说明）。
