### 4.92 图片标识符的排版：它必须**按正文排版**

**用户第一次报障**（原话）：

> 请优化下，无论什么时候，图片的标识符出现的时候和正文保持水平一致，现在如果在已有图片的
> 下方再插入图片，点击出现标识符后，标识符**为了在顶部显示，和正文脱节严重**。

**根因**：标识符是"文档里的正文原位文本"（第五十九轮的设计，不是浮层），但它的
`vertical-align` 一直是 **`top`** —— 那会把标识符**整块**顶到行盒顶端。含图片那一行的
行盒会被图片撑高，于是标识符跑到图片顶部，与同一行里的正文不在一条水平线上。

**第一次修（走了弯路，被用户否掉）**：把它改成"压成一行 + 省略号"的窄盒
（`display:inline-block` + `max-width: min(46ch,92vw)` + `overflow:hidden` + `text-overflow:ellipsis`）。
它确实治住了长 src（578 字符的 data URI 从 8 行 258px 压成 1 行 32px），但引入了新问题 ——
**用户第二次报障**：

> 这个图片是点击图片并点击图片的源码时的样子……好像源码有一个**最大宽度，显示不全**，
> 只有在点击源码后才会全部出现，而且源码出现的和**正文布局和排版不一致**。

即：窄盒把源码截断了（`显示不全`）、并且窄盒居中 + 只占 46ch 宽（`和正文排版不一致`）。

**定稿口径：标识符完全按正文排版** —— 与段落同宽、随段落对齐、长 URL 自然折行、
**完整显示**；**唯一**的样式改动是 `vertical-align`：

```css
/* src/renderer/src/assets/markdown.css —— .md-preview .img-src-revealed */
vertical-align: baseline;   /* 原来是 top */
```

为什么是 `baseline`：它让标识符**第一行的基线**落在正文那一行的基线上，与任何普通正文
文本一致；折行出来的后续行按正常行高往下排。

**为什么不用另外两个候选值**（都实测过）：

| 候选 | 结果 |
|---|---|
| `top`（原值） | 标识符整块顶到行盒顶端；标识符比图片矮时跑到图片顶部，与正文不在一条线（**用户第一次报障的成因**） |
| `middle` | 只对**单行**盒子成立；标识符一折行就以文字行为中心上下对称铺开、压到上一行去 |
| `baseline` ✅ | 第一行落在正文那一行上；折行行按正常行高往下排 |

**验收（`_verify-image-ui.js`，42/42）**：

- **③** 与图片同一行时标识符第一行贴在该行上（`vertical-align: baseline`，`diffTop < diffCenter`）；
- **③b** 长 src 按正文折行：与图片同处一行的那一段贴住该行，其余行按正常行高（4 段、行高 32/32/32，不整块上移）；
- **③c** 短标识符 + 高图（测试里把 widget 的 `<img>` 撑到 120px）：标识符落在**正文那一行**上，垂直中心差 ≤ 一个行高；
- **③d** **反向对照**：同一夹具下把 `vertical-align` 强行改回 `top`，差值必须**变大** —— 证明 ③c 有区分度，也把"`top` 就是成因"钉成可复跑的数字。

**试错记录（留给后来人，别再走一遍）**：

1. `overflow` 不是 `visible` 的 inline-block，其**基线取下外边距边缘**（CSS 规定），
   所以窄盒方案里用 `baseline` 会让标识符文字比正文高 10px —— 当时只能改用 `middle`。
   定稿方案没有 `overflow`，`baseline` 才成立。
2. **inline-block 的 `max-width` 不能写成百分比**：百分比在**固有尺寸计算**里按 `auto` 处理，
   而 `white-space: nowrap` 的超长单行会把段落的 max-content 撑到几千像素 ——
   实测把编辑区内容列从 **928px 顶到 1208px**，于是"居中图片"重新居中、水平位移 **140px**
   （`⑧①/⑧②/④/④c/②D` 五格全红）。修法是用 `min(46ch, 92vw)` 这类不依赖容器宽度的上限。
   ——该方案虽已被否，但这条坑对**任何**要做"超长单行不换行"的地方都成立。
3. 长 src（data URI）现在会按正文排成多行（578 字符 ≈ 8 行）。**这是"完整显示源码"的必然
   结果，不是缺陷**：想同时做到"显示完整"和"不占地方"是矛盾的，用户已明确选择前者。
